# Publication review — 2026-10-07

Scope: local Demokratiløftet demo applications and private infrastructure source.
The existing `server-infrastructure` and `organisation-verifier` repositories were
identified before creating repositories. Public `.github` and unrelated
`user-stories` are outside the application publication scope.

## Changes and findings

- Restored the calendar's 24-character minimum shared administrator key.
- Unified public-calendar behavior in the canonical app, preserving anonymous
  record denial, fixed-PDS OAuth and disabled shared admin/seed routes.
- Removed repeated parsing of malformed URLs in calendar error handling.
- Restricted direct issuer startup to loopback, refused empty client tokens,
  added Host/Origin validation, and stopped logging full internal exceptions.
- Fixed a real social-fixture startup race: static DNS `.2` collided with Docker
  dynamic allocation. Dynamic addresses now use a separate pool.
- Made the social fixture self-contained, with explicit vendored provenance.
- Updated vulnerable social build dependencies. Upgraded the local PDS fixture
  and pinned patched transitive dependencies; kept its isolation boundary.
- Added CI, full-history secret scans, dependency audits, weekly Dependabot,
  security policies, and reproducible setup/deployment instructions.
- Consolidated both unpublished infrastructure branches without changing live
  PDS data, submodule pins, or the existing VPS infrastructure branch.
- Hardened the organisation verifier's error responses and runtime containers.
  Updated its isolated PDS fixture dependencies and added real network isolation
  checks, including denial of external DNS and TCP.
- Added restricted, per-repository deployment triggers, ephemeral repository read
  tokens, exact-commit checks, health checks and automatic image rollback. Shared
  PDS/network/schema/fixture changes cannot enter through an ordinary app deploy.

## Limits

This is a code/configuration review and regression run, not an independent
penetration test or a guarantee that all software is secure. Container OS/base
images and every upstream service were not comprehensively vulnerability-tested.
The Spaces PDS is pinned alpha software. The sandbox's patched transitive overrides
include feature paths (telemetry, mail, media) that its tests do not activate.
It must remain isolated and synthetic-only.

The apps are single-process demos with documented storage, concurrency and
recovery limits. No real NIF/BankID/police integration, production membership
verification, cross-app SSO, or automatic production backups is claimed.
Automated app rollout preserves existing persistent storage; shared infrastructure
and alpha PDS migrations stay under deliberate operator control.
